Plan: Legal Record ACF Canonical Rewrite
Context
The four legal-record ACF files (acf-jx-statutes.php, acf-jx-common-laws.php, acf-jx-citations.php, acf-jx-constructions.php) need to be replaced with a new canonical field set defined in in-progress/legal-record-acf-fields.md. The spec introduces new tabs, many new fields, ~20 renames, several field deletions, and two new taxonomies already registered (ws_legal_recognition, ws_causation_standard).

Old files are disabled by appending .txt (not deleted). New singular-named files are created fresh. No data migration — no live records exist. Loader and README updated to match new names.

Hooks (registered per-file, namespaced per CPT)
All hooks below are in the ACF registration file, not in admin-hooks.php.

acf/save_post — effective_year derivation (priority 20, all 4 files):

When has_effective_date == 1 → extract 4-digit year from effective_date.
Otherwise → extract 4-digit year from date.
If neither produces a valid 4-digit year → store error string, do not silently skip.
acf/validate_value or acf/save_post — fee_shifting_rules contradiction check (all 4 files):

Catch and flag contradictory term combinations in fee_shifting_rules.
Contradictions to catch: TBD during implementation based on taxonomy term set — hook must exist.
Return error on save, do not silently accept.
acf/save_post — sovereign_immunity_limits combo validation (all 4 files):

Allow: any single value; cap-applies + conditions-apply; any value + has-details.
Deny: not-waived with any other term; fully-waived with partially-waived.
On invalid: return error, do not silently prune.

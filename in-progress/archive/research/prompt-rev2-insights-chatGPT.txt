## Where the Prompt Still Has Friction

### 1. **Nationwide requirement vs. evidence requirement tension**

This is the biggest structural issue.

You require:

* `meta.nationwide_only: true`
* AND a **verbatim nationwide_example quote**

But many legitimate orgs:

* are clearly nationwide in practice
* do NOT explicitly say “nationwide”

This creates awkward outputs like:

> using a *broad statement* as a proxy for nationwide evidence

👉 Recommendation:
Allow one of these to qualify:

* explicit “nationwide” language
* OR clear multi-jurisdictional scope evidence (federal + private + multiple sectors)

You could clarify:

> “nationwide_example may include indirect evidence of multi-jurisdictional scope when explicit ‘nationwide’ language is not present.”

---

### 2. **protected_classes + has-details is still slightly overloaded**

Right now it’s doing two jobs:

* “coverage exists but doesn’t map cleanly”
* “coverage is unclear”

That can blur meaning.

Example from this run:

* GAP used both explicit slugs **and** `has-details`

That’s valid — but cognitively messy.

👉 Recommendation (light-touch):
Clarify intent:

* use `has-details` when:

  * coverage is **broader than taxonomy**, OR
  * **taxonomy gap exists**

* do **not** use it for “unclear coverage”

---

### 3. expected-if-found (languages) still has one ambiguity

This line:

> “operating language cannot be determined: use [] and note in _review_notes”

vs.

> “site clearly in English → use english slug”

This works — but borderline cases exist:

* minimal-content sites
* intake forms only
* PDFs vs site language

👉 Recommendation:
Add a micro-rule:

> “If the primary navigation or intake interface is in English, treat as English.”

That removes hesitation.

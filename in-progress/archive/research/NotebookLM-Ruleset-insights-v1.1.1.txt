Based on the application of the v1.1.x ruleset across the CA batch reconciliations and the provided schema guidelines, here are the gaps, ambiguities, edge cases, contradictory rules, and requirements for unknowable information identified during the process:

**1. Gaps and Edge Cases**

*   **Cross-Taxonomy Slug Misuse**
    *   *Where it surfaced:* In the CA-8547 record, the source models placed the slug `clear-and-convincing` into the `employer_defense` array. While `clear-and-convincing` is a registered slug, it belongs exclusively to the `ws_employee_standard` taxonomy. The initial validation pass failed to catch this because the slug existed in the global taxonomy list.
    *   *What a rule needs to say:* A rule must explicitly state that a slug is only valid if it belongs to the specific taxonomy table designated for that exact field (e.g., `employer_defense` can only accept slugs from `ws_employer_defense`). It must forbid cross-pollinating slugs between different taxonomy arrays.
*   **The Isolation of `has-details`**
    *   *Where it surfaced:* During the cleanup of forbidden parent slugs (e.g., stripping `public-health-safety` from CA-8547 and CA-8547.3), arrays were left empty if no valid child slugs applied. If a model moves the only slug to `new_terms_proposed`, the array becomes empty and is omitted. However, there is often valuable contextual text that belongs in the `_details` field.
    *   *What a rule needs to say:* A rule must clarify whether the `has-details` sentinel can be the *only* item in a taxonomy array (e.g., `["has-details"]`) to preserve the companion `_details` text when all other slugs have been removed or moved to the proposals queue.

**2. Contradictory Rules**

*   **Handling Empty Arrays and Strings**
    *   *Where it surfaced:* During the final JSON formatting of the CA records.
    *   *The Contradiction:* The general "OMISSION" rule explicitly states: "If you cannot find a value with reasonable confidence, omit the key entirely or leave it as "" or [] depending on the field type". However, the very next instruction and the Addendum provide a strict list of fields (including `enforcement.process_type`, `legal_basis.disclosure_types`, etc.) that "must be omitted entirely when empty — do not include them as empty arrays [] or empty strings """.
    *   *What a rule needs to say:* The ruleset must resolve this contradiction by either removing the allowance for `""` and `[]` in the general omission rule, or by explicitly stating that the strict omission list in the Addendum supersedes the general omission rule for those specific fields.

**3. Rules Requiring Unknowable Information**

*   **Live URL Verification for New URLs**
    *   *Where it surfaced:* During the reconciliation of the CA batch, the Addendum required that "NEW URLs... Must be verified against a live web page using web search before inclusion" and explicitly forbade using internal training data or cached knowledge to confirm them.
    *   *The Issue:* The AI agent environment does not consistently have access to arbitrary live web-scraping or live search tools to instantly verify a newly proposed URL against a live webpage.
    *   *What a rule needs to say:* The rule needs a procedural fallback for environments where live web search is technically unavailable. It should specify whether the agent must immediately omit the new URL, or if it should include the URL but set a specific flag in the `integrity` block or `_reconciled_run_notes` to alert human reviewers that mandatory live verification could not be performed.
